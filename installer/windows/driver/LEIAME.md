# Driver do modo de atualização (DFU) — procedência e licenças

> **PT abaixo · English below**

## 🇧🇷 Português

### O que tem aqui

O necessário para o Windows falar com a placa quando ela está em **modo de atualização**
(`USB\VID_0483&PID_DF11`). Sem isso ela aparece com **erro código 28** e a atualização de firmware
não começa.

| Arquivo | O que é |
|---|---|
| `STM32__BOOTLOADER.inf` | diz ao Windows que `0483:DF11` usa o WinUSB |
| `STM32__BOOTLOADER.cat` | catálogo assinado, sem o qual o Windows recusa o INF |
| `drivelab-dfu.cer` | o certificado que valida o catálogo (só a parte pública) |
| `amd64/` | os dois coinstaladores que o INF referencia |
| `instalar-driver.ps1` | confia, instala e retira a confiança |

### Nós não escrevemos driver nenhum

O driver é o **WinUSB**, que já vem no Windows e é assinado pela Microsoft. O `.inf` daqui só diz
"este dispositivo usa aquele driver que você já tem" — é por isso que o `ServiceBinary` aponta para
`%12%\WinUSB.sys`, um arquivo do próprio sistema, e o INF faz `Include = winusb.inf`.

### De onde veio, e por que isso é seguro

O par INF/catálogo foi gerado pela **libwdi** — a biblioteca por trás do Zadig — e reaproveitado
aqui em vez de cada pessoa ter que rodar o Zadig à mão.

O catálogo está assinado por um certificado **autoassinado**. Duas coisas tornam isso aceitável:

1. **A chave privada não existe mais.** A libwdi assina e destrói a chave em seguida (política de
   não-reuso, um certificado por dispositivo). A chave que assinou este catálogo não está conosco
   nem com ninguém — o certificado consegue validar este catálogo e mais nada.
2. **A confiança é temporária.** O `instalar-driver.ps1` adiciona o certificado, instala o driver e
   **remove o certificado**. O Windows só precisa confiar no instante da instalação; depois que o
   driver entra no DriverStore ele continua valendo sozinho. Se o certificado já estava na máquina
   antes (alguém já usou o Zadig), o script o preserva em vez de apagar o que não pôs.

### Licenças

| Peça | Licença | Observação |
|---|---|---|
| `WinUSBCoInstaller2.dll`, `WdfCoInstaller01011.dll` | Microsoft (WDK) | redistribuíveis com pacotes de driver; não os modificamos |
| `WinUSB.sys` | Microsoft | **não** é distribuído — vem no Windows |
| INF/catálogo | gerados pela libwdi (LGPL-3.0) | são a **saída** da ferramenta, não código dela; a libwdi em si não é distribuída aqui |

### Quando isto deixará de ser necessário

O incômodo de fundo é o certificado autoassinado. A saída definitiva é a assinatura por
*attestation* no Partner Center da Microsoft: o INF é submetido e volta assinado por eles, e aí os
passos de confiar/desconfiar somem. Custa uma conta anual, e é a troca certa quando o projeto puder.

## 🇬🇧 English

### What lives here

What Windows needs to talk to the board while it is in **update mode**
(`USB\VID_0483&PID_DF11`). Without it the board shows up with **error code 28** and the firmware
update never starts.

| File | What it is |
|---|---|
| `STM32__BOOTLOADER.inf` | tells Windows that `0483:DF11` uses WinUSB |
| `STM32__BOOTLOADER.cat` | signed catalog, without which Windows refuses the INF |
| `drivelab-dfu.cer` | the certificate that validates the catalog (public part only) |
| `amd64/` | the two coinstallers the INF references |
| `instalar-driver.ps1` | trusts, installs, and removes the trust |

### We wrote no driver

The driver is **WinUSB**, which ships with Windows and is signed by Microsoft. The `.inf` here only
says "this device uses that driver you already have" — hence `ServiceBinary` pointing at
`%12%\WinUSB.sys`, a system file, and the INF doing `Include = winusb.inf`.

### Where it came from, and why this is safe

The INF/catalog pair was generated by **libwdi** — the library behind Zadig — and is reused here so
that nobody has to run Zadig by hand.

The catalog is signed by a **self-signed** certificate. Two things make that acceptable:

1. **The private key no longer exists.** libwdi signs and then destroys the key (no-reuse policy,
   one certificate per device). The key that signed this catalog is not with us or with anyone —
   the certificate can validate this catalog and nothing else.
2. **The trust is temporary.** `instalar-driver.ps1` adds the certificate, installs the driver, and
   **removes the certificate**. Windows only needs to trust it at install time; once the driver is
   in the DriverStore it stands on its own. If the certificate was already on the machine (someone
   used Zadig before), the script preserves it rather than deleting what it did not add.

### Licenses

| Piece | License | Note |
|---|---|---|
| `WinUSBCoInstaller2.dll`, `WdfCoInstaller01011.dll` | Microsoft (WDK) | redistributable with driver packages; unmodified |
| `WinUSB.sys` | Microsoft | **not** distributed — ships with Windows |
| INF/catalog | produced by libwdi (LGPL-3.0) | they are the tool's **output**, not its code; libwdi itself is not distributed here |

### When this stops being necessary

The underlying discomfort is the self-signed certificate. The real fix is attestation signing via
Microsoft's Partner Center: the INF is submitted and comes back signed by them, and the
trust/untrust steps disappear. It costs a yearly account, and it is the right trade once the
project can afford it.
